# 系统功能与配置迁移

「系统功能」集中管理配置迁移、操作审计和控制台用户。配置迁移使用 JSON 文件，在新环境导入管理配置，无需复制 RocksDB 数据目录。

## 页面操作

1. 源集群打开「系统功能 → 配置迁移」，导出 JSON。
2. 将文件加密保存；它包含数据源密码、设备认证凭据、模型 API Key 和证书私钥。
3. 在目标集群先导出一份备份，再上传来源文件并执行预检。
4. 查看新增、覆盖、跳过数量及警告；按需选择覆盖和监听端点。
5. 确认导入后检查结果、数据源连接和运行节点配置。

默认合并：已有同名或同 ID 对象保留，不删除目标独有对象。开启覆盖后才替换匹配对象及配置组设置。监听端点单独选择，变更可能导致监听重启。

## 迁移范围

| 内容 | 行为 |
| --- | --- |
| 数据源、规则、函数、指令消费 | 导出并按导入选项合并 |
| 设备认证、ACL、黑白名单 | 导出并按导入选项合并 |
| AI 模型及 API Key | 持久化模型配置参与迁移 |
| 监听、证书与私钥 | 文件包含，监听导入需要单独选择 |
| 控制台用户、密码、角色 | 不导出；旧文件中的此类字段也不覆盖目标账号 |
| `assistant_runtime` | 不导出；使用目标 `config.toml` 中的运行参数 |
| License、节点 ID、集群成员、JWT 密钥 | 不迁移 |
| 会话、订阅、保留/延迟/离线消息、审计历史 | 不迁移；本文件不是消息备份 |

导出递归省略对象中值为 `null` 的字段，保留 `false`、`0`、空字符串和空集合。设备认证用户参与迁移，与控制台用户不是同一类账号。

## API

仅已登录管理员可使用，携带 `Authorization: Bearer <token>`：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/config/export` | 下载配置 JSON |
| `POST /api/config/import/preview` | 校验配置，获取 `preview_token` |
| `POST /api/config/import` | 使用相同配置、选项及令牌正式导入 |

```json
{
  "config": {"format":"velamq-management-config","format_version":1},
  "overwrite": false,
  "include_endpoints": false
}
```

上例展示请求外层结构，`config` 必须替换为完整导出对象。正式导入额外填入预检返回的 `preview_token`。预检后目标配置变化时返回 409，需要重新预检。

## 结果与安全

- `completed`：保存及同步加载调用完成。
- `partial`：存在部分写入，后续分组未全部执行；先核对再重新预检。
- `saved_reload_pending`：已保存，但运行时加载仍需检查日志和节点状态。

不能只用 HTTP 200 判断导入全部成功。导入不是跨配置组事务，不自动回滚；导出也不是跨组原子快照，操作期间应暂停其他配置修改。不要同时向多个节点发起导入。外部服务地址、文件路径和凭据需要按目标环境核对。
