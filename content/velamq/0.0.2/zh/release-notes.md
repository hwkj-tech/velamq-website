# VelaMQ 0.0.2 版本说明

0.0.2 文档重点覆盖规则模板函数、外部离线消息存储、管理配置迁移，以及 Prometheus 监控。文档中的配置名称和行为对应当前实现。

## 主要变更

| 模块 | 使用方式与变化 |
| --- | --- |
| 模板内置函数 | 已支持上下文模板的规则动作、设备认证、ACL 和指令消费，可使用 `${lower(client_id)}` 等函数及嵌套调用 |
| Redis 离线消息 | 选择 Redis 数据源并设置过期时间；消息键、存储格式、查询及删除由系统管理，无需填写 SQL 或 Redis 命令 |
| MySQL 离线消息 | 按客户端保存多条消息；通过保存、查询、确认删除三条 SQL 对接业务表 |
| 离线补发 | 持久会话恢复或订阅生效后补发；QoS 1 在 PUBACK 后清理，QoS 2 在 PUBCOMP 后清理 |
| 配置迁移 | 在「系统功能 → 配置迁移」导出 JSON，预检后导入；控制台账号和节点本地配置不迁移 |
| 黑白名单 | 启用规则后自动参与连接检查；黑名单优先，存在白名单时仅允许命中白名单的连接 |
| 监控 | 外部 Prometheus 负责历史采集；移除内置监控历史页及业务 RocksDB/Raft 中的监控采样写入 |
| 分片指标 | 默认按节点、业务空间汇总；仅排障时开启 `shard_details=true` |

## 使用入口

- 规则引擎：事件 SQL、动作配置、模板以及规则测试。
- 函数管理：自定义 Rhai、Lua、Wasm 函数的定义、测试和启停。
- 数据源：Redis、MySQL 等外部连接及连接参数。
- 系统功能：配置迁移、操作审计、控制台用户。
- 仪表盘：实时资源信息、连接状态以及当前运行节点的软件版本。

## 兼容性与升级

Redis 离线存储采用新内置信箱。旧版自定义 Redis key/value 不会自动转换；升级前应处理原有积压，且不要随意更改有积压规则的规则 ID、动作 ID 或数据源。

监控历史在升级后由每个节点后台分批清理；需要保留旧历史时应先备份。会话、保留消息、延迟消息和业务配置不属于这项清理范围。

管理配置 JSON 是配置迁移文件，不是 RocksDB、会话或消息数据备份。导入不会创建、覆盖或删除目标集群的控制台用户。

## 已知问题

外部离线保存队列在突刺下满载时，部分消息会回退原生队列。当前两类积压混合恢复可能出现同一设备的消息乱序，Redis 和 MySQL 均已复现。要求严格顺序的业务，应在该问题修复并完成回归后采用此模式。

外部离线保存为异步处理，发布端收到 PUBACK 不代表 Redis/MySQL 已提交。不要将此行为作为跨 Broker 与外部数据库的事务保证。

## 验证范围

真实 Redis/MySQL 测试覆盖多条离线消息、客户端隔离、部分确认后重连、QoS 2 确认清理、二进制载荷、Redis 过期及订阅权限检查。批量测试覆盖单设备 10,000 条和 20 台设备合计 100,000 条消息的受控积压恢复；突刺混合恢复的顺序问题仍待修复。这些是本机单节点测试结果，不作为集群容量结论。
